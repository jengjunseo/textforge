# TextForge 프로젝트 브리핑

마지막 대조일: 2026-08-11  
현재 제품 기준: **TextForge v1.0 Local**

이 문서는 TextForge의 현재 상태를 다음 개발 세션에 인계하기 위한 단일 기준 문서다. 과거 작업 일지나 계획을 보존하는 문서가 아니라, 현재 코드와 테스트에서 확인되는 제품 구조, 안전 계약, 남은 한계와 다음 판단 지점을 설명한다. 내용이 코드와 충돌하면 추측으로 문서를 늘리지 말고 코드와 관련 회귀 테스트를 먼저 확인한다.

## 1. TextForge 한눈에 보기

TextForge는 서버, 계정, 클라우드 동기화 없이 브라우저 프로필에 문서를 저장하는 개인용 Rich Text 문서 작업공간이다.

> 서식은 풍부하게, 출력은 깨끗하게.

주요 사용 경험은 다음과 같다.

1. 앱을 열면 마지막 문서와 가능한 마지막 편집 위치가 복원된다.
2. Rich Text 편집기에서 바로 입력한다.
3. Sidebar에서 자주 쓰는 문서로 빠르게 전환하고, Portal Library에서 전체 문서함을 관리한다.
4. Smart Copy 또는 Export Studio로 목적에 맞는 출력을 만든다.
5. History, Safety Snapshot과 Forge Snapshot으로 복구와 장기 보존 경로를 확보한다.

현재 단계는 로컬 웹 앱과 Windows app mode를 중심으로 한 v1 기준선이다. PWA manifest와 launcher는 있지만 Tauri/Electron 앱, 계정, 원격 데이터베이스, 웹 동기화는 도입하지 않았다.

## 2. 현재 구현 상태

### 작성과 편집

- `contenteditable` 기반 Rich Text 편집
- Write, Preview, Split 기본 보기와 More 메뉴의 Source 편집
- 제목, 태그, 즐겨찾기, 문서 모양 preset
- 글꼴, 크기, 굵게/기울임/밑줄, 색상, 배경, 정렬, 링크, 이미지, 표 등 Rich Text 도구
- 현재 selection 종류에 맞는 Contextual Inspector
- 두 문서를 동시에 편집할 수 있는 reference pane과 분할 방향/비율/스크롤 상태
- 문서 탭 열기, 닫기, 다시 열기, 순서 변경과 키보드 탐색
- Focus Mode와 편집 폭 조절, Light/Dark/System theme
- 문서 링크, 백링크, 목차, Prompt Vault
- Quick Note: Inbox/폴더에 새 문서를 만들거나 현재·선택 문서에 append하는 단일 빠른 입력 경로

### 문서 탐색과 관리

- Sidebar: 최근 문서 중심의 저지연 전환, 즐겨찾기·폴더·검색 진입
- Portal Library: 전체 문서함의 grid/list, 검색, 정렬, 계층 폴더, breadcrumb, 스마트 폴더, 컬렉션
- Portal 다중 선택, 키보드 탐색, drag 이동, 폴더 이동, 실행 취소, 휴지통과 복원
- Quick Look: 문서를 편집기로 열지 않고 sanitize된 복사본을 읽고 검색
- Universal Command (`Ctrl+K`): 문서, 폴더, 보기, 설정과 명령을 하나의 metadata 검색 경로로 탐색

Main 내부의 중복 Finder 문서 관리 화면은 제거됐다. **Sidebar는 빠른 전환, Portal은 전체 관리, Universal Command는 즉시 검색**이라는 역할 구분이 현재 기준이다.

### 출력과 보존

- Smart Copy: Plain, Rich, Markdown, Board
- Export Studio: TXT, Markdown, HTML, DOC, PDF, EPUB, PNG Card
- Export preview와 실제 출력은 공통 artifact builder와 기존 renderer를 사용한다.
- Forge Snapshot: 문서함을 하나의 읽기 전용 HTML 아카이브로 생성
- AI 출력 정리: 원본을 보존하고 정리 결과를 새 문서로 생성

Forge Snapshot은 현재 편집기 import 파일이 아니다. HTML 내부 데이터는 복구 원천이 될 수 있지만 자동 import/merge 기능은 구현되지 않았다.

### 저장과 복구

- 입력 후 debounce 자동저장과 문서 전환·출력 전 full flush
- IndexedDB durable snapshot과 이전 snapshot backup
- localStorage 호환 key와 preference
- 저장 문서 수가 갑자기 줄어드는 쓰기를 거부하는 anti-shrink guard
- 마지막 active 문서, view mode, scroll, caret/selection을 담는 세션 복구
- 문서별 History Snapshot과 위험 작업 전 Safety Snapshot
- 일반 입력의 browser native Undo와 구조적 bulk 작업의 app-level Undo/Redo
- Visual Versions의 비교, 전체 복원, 부분 삽입과 새 문서 생성
- Quick Note와 cross-document selection 작업의 operation id, revision 검사, rollback

### 고급 로컬 작업공간

- 최대 20개의 이름 있는 Workspace: 탭, Split, Inspector/Focus와 view state만 저장하며 본문은 저장하지 않음
- Detached Editor: 한 문서의 편집 lease를 별도 창에 위임하고 Reattach로 회수
- Selection as Object: 선택 영역 복제·삭제·새 문서·다른 문서로 copy/move·문서 링크
- Quick Look 공통 controller: Main, Portal, Workspace, backlink, Split, Detached에서 읽기 전용 preview 제공
- Diagnostics/Benchmark/MTTR/Release Gate와 Lab 전용 stress 도구

## 3. 핵심 아키텍처

### 실행 구조

- `dev-server.js`는 `127.0.0.1:4291`에서 정적 파일만 제공한다.
- `Start TextForge.cmd`와 `launch-textforge-app.bat`는 서버를 확인한 뒤 Edge/Chrome app mode를 연다.
- 앱은 backend API나 외부 네트워크 client를 사용하지 않는다.

Main 로드 순서:

1. `styles.css`, `textforge-quick-look.css`
2. `forge-snapshot.js`
3. `textforge-diagnostics.js`
4. `portal-library-core.js`
5. `textforge-universal-command.js`
6. `app.js`
7. `textforge-quick-look.js`
8. `macintosh-experience.js`

핵심 파일:

| 파일 | 책임 |
|---|---|
| `index.html`, `styles.css` | Main DOM과 canonical 사용자 화면 |
| `app.js` | 문서 모델, 편집, 저장, 문서 전환, 출력, 명령과 단일 writer |
| `macintosh-experience.js` | 탭, Workspace, Quick Note, Export Studio, Versions 등 UI 계층 |
| `portal-library-core.js` | 문서를 수정하지 않는 검색·정렬·선택·폴더 순환 검사 |
| `portal-library.html/css/js` | 별도 Portal 창과 Main command bridge |
| `detached-editor.html/css/js` | 저장소에 직접 접근하지 않는 lease 기반 별도 편집 창 |
| `textforge-quick-look.js` | 공통 read-only preview controller |
| `forge-snapshot.js` | 읽기 전용 archive 생성 |
| `textforge-diagnostics.js` | read-only clone/memory-only 진단 |

### 상태와 저장 권한

`app.js`가 문서와 폴더의 유일한 영속화 권한자다. `window.TextForgeExperienceHost`는 복사된 상태와 명시적 action만 UI 계층에 제공한다.

주요 저장 계약:

| 저장 항목 | 현재 값/역할 |
|---|---|
| IndexedDB | `textforge-personal-storage`, version `1`, store `state` |
| Durable current | `state:snapshot` |
| Durable backup | `state:snapshot-backup` |
| 문서 fallback | `textforge.documents.v1` |
| active 문서 | `textforge.activeDocument.v1` |
| 세션 복구 | `textforge.sessionRecovery.v1` |
| 폴더/프롬프트 | `textforge.folders.v1`, `textforge.prompts.v1` |
| durable pointer | `textforge.pointer.v2` |
| Split | `textforge.splitWorkspace` |
| Macintosh UI | `textforge.macintoshExperience.v1`, schema 2 |
| Portal preference | `textforge.portalLibrary.preferences.v1` |
| Quick Note draft | sessionStorage `textforge.quickNoteDraft.v1` |

문서 모델의 핵심 필드는 `id`, `title`, `content`, `contentHtml`, `plainText`, `previewText`, `searchText`, `type`, `folderId`, `tags`, `favorite`, `history`, `createdAt`, `updatedAt`, `wordCount`, `charCount`다. 구형 문서는 `normalizeDocuments()`에서 누락 필드를 보완해 읽는다.

### 편집 입력 동기화

긴 문서 입력은 fast sync와 full sync를 분리한다.

- `syncRichToDocumentFast()`: `richEditor.innerHTML`을 메모리의 active 문서에 반영하고 dirty/persist/full-sync를 예약
- `syncRichToDocumentFull()`: sanitize, Markdown 변환과 derived metadata 갱신
- full flush 시점: 저장, 문서·mode 전환, Export, Snapshot과 명시적 작업 전
- IME composition 중에는 무거운 동기화와 selection 복원을 피한다.
- deferred 작업은 대상 문서/token이 바뀌면 폐기한다.

### 창 사이의 경계

Portal은 `BroadcastChannel("textforge.portal-library.v1")`와 same-origin `postMessage` fallback을 사용한다. 일반 state에는 metadata만 있고 본문은 없다. Quick Look 요청 때만 선택한 한 문서의 sanitize된 copy를 받는다. move, rename, favorite, trash, restore, folder와 Quick Note 열기 요청은 Main이 검증하고 저장한다.

Detached Editor는 `textforge.detached-editor.v1` 채널에서 document lease, request id와 base revision을 사용한다. 저장소나 IndexedDB를 직접 열지 않는다. 연결이 끊기면 read-only로 바뀌고 미전송 draft는 sessionStorage에 남긴다.

## 4. 절대 깨지면 안 되는 제품 계약

1. **Local-first**: 사용자 문서는 브라우저 프로필에 있으며 repository/Git commit은 문서 백업이 아니다.
2. **저장 호환성**: storage key, IndexedDB 이름·version, 문서 schema를 migration/rollback 없이 변경하지 않는다.
3. **원본 보호**: theme, Focus, 줄바꿈, Preview, Quick Look, Portal 탐색, Diagnostics 같은 display/read-only 동작은 `content`나 `contentHtml`을 바꾸지 않는다.
4. **입력 fast path**: 매 keystroke에 sanitize, Markdown, 전체 검색 metadata, Preview, Inspector나 Portal 렌더를 넣지 않는다.
5. **단일 writer**: Main만 문서와 폴더를 저장한다. Portal은 metadata command client이고 Detached는 lease를 가진 제한된 writer view다.
6. **IME와 Undo**: composition 중 selection/구조 작업을 강행하지 않는다. 일반 입력은 native Undo를 유지하고 bulk 작업은 Safety Snapshot과 app Undo를 사용한다.
7. **트랜잭션 안전**: cross-document/Quick Note/Workspace 작업은 revision, request dedupe, 실패 rollback과 stale-write 보호를 유지한다.
8. **출력 안정성**: Smart Copy, Export 7종과 Forge Snapshot의 의미와 변환 경로를 관련 fixture 없이 대규모 변경하지 않는다.
9. **복구 우선**: 위험한 변환은 원본 덮어쓰기보다 Safety Snapshot 또는 새 문서 생성을 우선한다.
10. **격리 진단**: 실제 문서함 진단은 clone/read-only, stress는 memory-only여야 한다.

## 5. 안정화된 영역과 Freeze

다음 영역은 현재 회귀 테스트가 보호하는 제품 기준선이다. 새 기능과 직접 관련이 없으면 재설계하지 않는다.

| 영역 | 동결 이유 |
|---|---|
| storage key, IndexedDB v1, anti-shrink | 실제 사용자 문서의 연속성과 복구 경로 |
| `contenteditable` 편집 엔진과 fast/full sync 순서 | 17K 입력과 native Undo/IME 경로 |
| session resume v2와 구형 payload fallback | 실행 즉시 이어 쓰기와 손상 상태 fallback |
| Sidebar/Portal/Universal Command 역할 | 중복 Main Finder 제거 후 확정된 탐색 구조 |
| Quick Note 단일 경로 | legacy Quick Capture와 중복 저장 경로 제거 완료 |
| Export Studio와 renderer 7종 | 직접 Export UI 제거 후 단일 사용자 pipeline 확정 |
| Smart Copy와 Forge Snapshot | 출력·백업 호환성과 실제 archive 보존 |
| Portal metadata-only와 Main writer | 별도 창이 문서 본문을 오염하지 않는 안전 경계 |
| Detached lease/revision contract | 중복 writer와 stale write 방지 |
| History/Safety/Bulk Undo/rollback | 위험 편집의 복구 기반 |
| dark inline color adaptation, word wrap, Focus width | display-only 원본 불변 계약 |
| app mode launcher | 현재 Windows 데스크톱 사용 진입점 |

## 6. 중요한 결정

- **로컬 제품을 우선한다.** 계정, Supabase, cloud sync, 자동 업로드는 현재 범위가 아니다.
- **Main 화면은 작성에 집중한다.** Sidebar는 빠른 전환만 담당하고 전체 관리는 Portal로 보낸다.
- **하나의 목적에는 하나의 사용자 경로를 둔다.** 빠른 입력은 Quick Note, 파일 출력은 Export Studio다.
- **Source는 별도 문서 모델이 아니다.** Rich HTML과 source 변환은 기존 문서 pipeline 안에서 관리한다.
- **Forge Snapshot은 read-only archive다.** 현재 편집기로 직접 불러오는 기능으로 간주하지 않는다.
- **현재 editor engine을 유지한다.** Tiptap/ProseMirror 교체는 저장·Undo·IME migration을 포함하는 별도 고위험 결정이다.
- **Tauri/Electron은 보류한다.** app mode 안정성과 사용자 데이터 migration 계획이 먼저다.
- **계측 없는 최적화를 하지 않는다.** 실제 조건에서 병목 단계가 확인된 뒤 가장 큰 한 단계만 수정한다.
- **프로젝트 인계 문서는 이 파일 하나다.** 새 Architecture/Next Steps/ADR 묶음을 다시 만들지 않는다.

## 7. 현재 한계와 미완료

- 실제 사용자 브라우저 프로필과 실제 문서함에서의 장기 사용 검증은 자동 fixture로 대체할 수 없다.
- 실제 Windows app mode의 한글 IME, native Undo/Redo, Detached popup 배치와 재연결은 수동 확인 항목이다.
- PDF 최종 저장은 브라우저 native print dialog를 거치므로 자동 테스트가 완결하지 못한다.
- 물리적인 Windows 100/125/150/200% 배율과 실제 모니터 조합은 수동 확인이 남아 있다.
- 17K 입력은 예산 이내지만 문서 전환 next-frame은 실행 환경에 따라 약 20ms를 넘길 수 있다. Long Task나 `innerHTML` 병목이 확인되지 않으면 렌더 구조를 먼저 바꾸지 않는다.
- Forge Snapshot import/merge는 구현되지 않았다. 만들 경우 기존 문서 덮어쓰기 없이 선택 문서를 새 문서로 복원하는 prototype부터 시작해야 한다.
- Cloud/Web Mirror, 모바일 Rich Text 편집, 원격 DB, Tauri/Electron, service worker offline cache는 구현되지 않았고 현재 v1 범위 밖이다.
- 실제 사용자 문서는 repository에 없으므로 소스 백업과 문서 백업을 혼동하면 안 된다.

최근 기록된 격리 Edge 기준(2026-08-02)은 runtime error 0, 17K input p95 약 `0.6ms`, Long Task 0, 일반 문서 전환 next-frame p95 약 `22ms`, 17K 포함 약 `18.6ms`였다. Portal metadata benchmark는 39문서 p95 약 `0.08ms`, 1,000문서 p95 약 `2.32ms`였다. 이는 실제 사용자 프로필 성능을 대신하지 않는다.

## 8. 앞으로의 주안점

### 1순위: 실제 로컬 릴리즈 검증

실제 app mode와 사용자 문서함에서 한글 IME, Undo/Redo, 문서 전환, Smart Copy 4종, Export 주요 형식과 Forge Snapshot 생성·열람을 확인한다. 사용자 데이터에는 장애를 주입하지 않는다.

### 2순위: 복구 경험 명료화

History, Safety Snapshot과 Forge Snapshot의 차이를 사용자가 쉽게 이해하도록 한다. Snapshot import가 필요하다면 preview 후 선택 문서를 **새 문서로만** 복원하는 범위에서 시작한다.

### 3순위: 조건부 성능 관찰

실제 앱 모드에서 전환 p95가 반복적으로 100ms 이상 튈 때만 trace를 수집한다. `renderDocList`, panel, split, save 충돌, 특정 문서 DOM 중 가장 큰 한 단계만 후속 대상으로 선택한다.

### 4순위: 회귀 자동화 유지

UI 경로를 바꾸면 stale selector를 제품 결함과 구분하고, 저장/본문 불변·writer 권한·입력 fast path assertion은 완화하지 않는다.

웹 동기화, 모바일 편집과 native packaging은 위 기준선과 migration 계획이 충분히 검증된 뒤 별도 제품 결정으로 다룬다.

이 테스트는 임시 Edge profile을 사용한다. 실제 프로필 측정은 사용자가 앱 내부에서 직접 실행해야 의미가 있다.

### 변경 영역별 시작 파일

| 작업 | 시작 파일/함수 |
|---|---|
| 입력·저장 | `app.js`: `syncRichToDocumentFast`, `syncRichToDocumentFull`, `persistSoon`, `persistNow`, durable storage 함수 |
| 문서 전환·Resume | `openDocumentInPane`, `renderActive`, session recovery 함수 |
| Main UI | `index.html`, `styles.css`, `macintosh-experience.js` |
| Portal | `portal-library.js`, `portal-library-core.js`, Main의 Portal bridge |
| Split/Detached/Workspace | `app.js`, `macintosh-experience.js`, `detached-editor.js` |
| Quick Look/Versions/Selection | `textforge-quick-look.js`, `macintosh-experience.js`, `TextForgeExperienceHost` |
| 출력 | `buildExportArtifact`, Export Studio, Smart Copy, `forge-snapshot.js` |
| 진단·성능 | `textforge-diagnostics.js`, Typing/Document Switch debug API와 관련 tests |

현재 자연스러운 다음 작업은 새 대형 기능이 아니라 **실제 로컬 릴리즈 수동 검증 또는 복구 경험의 안전한 명료화**다. 저장, editor loop, Export, Forge Snapshot이나 writer 경계를 건드리는 작업은 먼저 계측·fixture·rollback 계획을 준비한다.
